01The architect's view: where S3 fits

Read this section first. It gives the decision. The sections after it teach how object storage works.

In short: Amazon S3 stores files of any kind and any size as objects. You write a complete object with one request and read it back with its key. S3 keeps the data in several Availability Zones, scales with no limit on the number of objects, and lets a browser download an object directly. It is the place for images, documents, backups, logs and data lakes. It is not a database: it does not change a part of an object, and it has no queries over the content.

The key idea is the {{ k.term("object") }}: the bytes of a file plus metadata, stored under a key in a bucket. One request writes or reads the whole object.

The questions that an architect asks, in this order

  1. Is it a file or a record? Files go to S3. The record that describes the file (owner, price, status) stays in a database and stores the key.
  2. Who reads it, and how? A private bucket and presigned URLs, or a CDN in front. Never a public bucket by accident.
  3. Can a write be a mistake? Then turn on versioning, and a lifecycle rule for old versions.
  4. How often is it read after one month, after one year? That selects the storage class and the lifecycle rules.
  5. How do the keys look? Put the parts that you list by at the start of the key: uploads/<visitor>/.
  6. Must something happen after an upload? Then use event notifications to start the next step.

Where S3 sits in Lale Market

One private bucket holds two prefixes. products/ holds one image for each product. Its key is the product id, so the catalog needs no extra column to find it. uploads/ holds the files that visitors upload in the seller panel. Product pages load images through the S3 Engine App, and the seller panel can also give a presigned URL. Versioning is on, and a lifecycle rule deletes old versions after one day.

Part 1

Object storage: buckets, keys and objects

Keys and prefixes, metadata, versions and signed URLs.

02Why object storage? The cloakroom

A file system has folders, and a program can open a file, change byte 1,000 and close it. A block disk is even lower: it stores numbered blocks for one server. Object storage is simpler. It has one operation to put a complete object under a name, and one to get it back. This simple model is why it can grow to any number of objects and serve many readers at the same time.

{% call k.callout("analogy", "Analogy") %}

At a cloakroom, you give your coat and get a ticket with a number. You do not choose a shelf, and you cannot change a button on the coat while it hangs there. You show the ticket and get the whole coat back. S3 is the cloakroom, the key is the ticket, and the object is the coat.

{% endcall %}

03Buckets, keys, objects and metadata

  • A {{ k.term("bucket") }} is a container for objects. Its name is unique, and it belongs to one AWS Region.
  • A {{ k.term("key") }} is the full name of an object in the bucket, for example products/P0001.jpg.
  • An object is the data plus metadata. System metadata includes the size and Content-Type. User metadata are your own headers that start with x-amz-meta-.

These are six example keys of the Lale Market bucket. The visitor ids are examples. The real upload keys also contain the time of the upload.

{{ k.sample("s3_keys", "keys in the Lale Market bucket", key=["key"]) }} {% call k.sql("A1", "The Seed puts one product image") %} 
s3.put_object(Bucket=bucket, Key="products/P0001.jpg", Body=body, ContentType="image/jpeg",
              Metadata={"name": "Alpen Kablosuz Kulaklik 1", "category": "Elektronik", ...})
Bucket=bucketThe bucket of the workshop. Its name contains the account and the Region.
Key="products/P0001.jpg"The key. It contains the product id, so the product page can build the key without a lookup.
Body=bodyThe bytes of the image. One request sends the complete object.
ContentType="image/jpeg"S3 returns this value in the Content-Type header, so the browser shows the bytes as an image.
Metadata={...}User metadata. S3 stores each pair as an x-amz-meta- header. The Seed writes plain ASCII here, because HTTP headers must carry plain text.
{% endcall %}

Identifiers: the catalog owns the product id. The S3 key borrows it, so the image and the product stay linked with no extra column. S3 owns the version id of each object version. The upload response returns it, and the seller panel shows it.

S3 is strongly consistent. After a successful write, overwrite or delete of an object, the next read request immediately gets the latest version of the object (Amazon S3 consistency).

{{ k.fig("s3-consistency.png", "client 1 writes color = red. Client 2 later writes color = ruby. Both reads after the second write return ruby.") }}

04Prefixes, not folders

A bucket is flat. The console shows folders, but they are only the common start of keys, the {{ k.term("prefix") }}. ListObjectsV2 can filter by a prefix and can group keys at a delimiter character (ListObjectsV2).

{% call k.sql("A2", "The seller panel lists the uploads of one visitor") %} 
s3.list_objects_v2(Bucket=bucket, Prefix="uploads/v-7f3a/", MaxKeys=12)
Prefix="uploads/v-7f3a/"Return only the keys that start with this text.
MaxKeys=12At most 12 keys in this response. If there are more, the response says IsTruncated and gives a continuation token.

05Versioning: an upload never destroys the old object

With {{ k.term("versioning") }} on, each PUT to a key adds a new version with its own version id. A DELETE without a version id does not delete data. It adds a delete marker, and a normal GET then returns 404. The old versions stay until you delete them with their version id, or a lifecycle rule deletes them.

{{ k.fig("s3-versioning-put.png", "a PUT of photo.gif into a versioning-enabled bucket adds a new version ID. The old version stays.") }} {{ k.sim("versions", "Two uploads and a delete") }} {% call k.callout("analogy", "Analogy") %}

Think of a photo album where you never take out a photo. A new photo goes on top of the old one, and a "deleted" note goes on top of all of them. Lift the top sheets, and the old photos are still there.

{% endcall %} {{ k.quiz("s3-q1", "Versioning is on. A user deletes report.pdf without a version id. 06Presigned URLs: short access to a private object

The Lale Market bucket blocks all public access. A browser has no AWS credentials. A {{ k.term("presigned URL") }} solves this: the application signs a URL for one operation on one object, with an expiry time. "The credentials used by the presigned URL are those of the AWS user who generated the URL" (Boto3: presigned URLs).

{% call k.sql("A3", "The seller panel signs a download link") %} 
s3.generate_presigned_url("get_object", Params={"Bucket": bucket, "Key": "products/P0001.jpg"}, ExpiresIn=300)
"get_object"The URL allows only a GET of the object.
Params={"Bucket": ..., "Key": ...}The one object that the URL opens.
ExpiresIn=300The URL is valid for 300 seconds. With SDKs, the maximum is 7 days. A URL that temporary credentials signed expires no later than those credentials.

Part 2

Amazon S3: the AWS service

Durability, storage classes, lifecycle and access.

07Durability, storage classes and lifecycle

S3 is a regional service. AWS states 11 nines (99.999999999%) of durability for S3, with the data stored across Availability Zones in one Region (AWS Storage Blog). There is no limit to the amount of data or the number of objects in a bucket.

Each object has a {{ k.term("storage class") }}. The classes differ in price per GB, in the cost of a read and in the time to get the data back. A {{ k.term("lifecycle rule") }} moves objects to another class, or deletes them, after a number of days.

08S3 in Lale Market

  • One bucket, dbws-images-<account>-<region>, with Block Public Access on, encryption SSE-S3 (AES256) and object ownership "bucket owner enforced".
  • The S3 Engine App reaches S3 through a gateway VPC endpoint and signs each request with its IAM role (SigV4).
  • The Seed deletes the objects under products/ and puts one image for each product, with name, category, author and license as user metadata.
  • The seller panel uploads files up to 2 MB to uploads/<visitor>/<time>-<file name>, with the product id as metadata, and lists them with ListObjectsV2.
  • Versioning is on. The lifecycle rule expire-old-versions deletes a version 1 day after it stops being the current version. The reset deletes the objects under uploads/.
